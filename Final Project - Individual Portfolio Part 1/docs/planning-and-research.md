# Planning and Research Notes

## Professional Direction

Target direction: applied AI product engineer.

Related roles researched:

- Applied AI Engineer
- AI Product Engineer
- Forward Deployed AI Engineer
- AI Engineering / AI workflow builder roles

Common responsibilities across these roles:

- translate ambiguous business or user needs into technical plans
- build working prototypes and production-minded AI workflows
- integrate APIs, data sources, retrieval systems, and evaluation loops
- communicate tradeoffs around cost, latency, data quality, and reliability
- use AI tools as part of an intentional workflow instead of treating them as shortcuts

## Course Tour Decisions

### 1. Figure out who it is for

Audience: a product or engineering reviewer hiring or evaluating an emerging AI-ready builder.

Need: the reviewer needs quick proof that I can build, explain, and improve practical tools.

Promise: the first screen should make it clear that I am moving toward applied AI product engineering and can connect technical work to real problems.

### 2. Pick the vibe

Chosen vibe: Sage plus creator.

Reason: applied AI roles require careful judgment and practical invention. The site should feel credible and structured, not flashy or inflated.

### 3. Choose the look

Visual direction: restrained systems-dashboard portfolio.

Design notes:

- use clear hierarchy and strong section labels
- keep the color system professional and not one-note
- use real project screenshots as proof
- avoid generic decorative art that does not support the work

### 4. Add proof people can trust

Proof appears near the main claim through:

- the revised affordability data story
- the CLI AI Toolkit project
- tool and skill tags
- course-framework process notes
- explicit AI workflow explanation

### 5. Turn it into a page

Page plan:

1. Hero with professional direction and key links
2. Quick proof strip
3. Featured work
4. Professional direction and skills
5. Course design-system process
6. AI workflow explanation
7. Contact and professional links

### 6. Put it live

The site is static so it can be published from GitHub Pages. The README includes the hosted link, repository link, GitHub profile, and LinkedIn profile.
